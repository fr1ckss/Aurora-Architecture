# Aurora Architecture

Открытая экосистема разработки Aurora Code. Этот репозиторий является **источником** общих стандартов и инструкций для ИИ-агентов; прикладные проекты (например, Havn) остаются самостоятельными.

## Структура

- `docs/ARCHITECTURE.md` — концепция и принципы экосистемы.
- `docs/STANDARDS.md` — каркас стандартов и планируемые направления.
- `ai/cursor/aurora-core.mdc` — общие инструкции Cursor.
- `ai/cursor/level-learning.mdc` — режим обучения.
- `ai/cursor/level-development.mdc` — режим разработки.
- `.cursor/rules/custom.mdc` внутри подключаемого проекта (не в этом репозитории) — необязательные персональные правила проекта.

## Подключение Cursor к проекту

В проекте (например, Havn) создайте папку `.cursor/rules/` и **скопируйте** туда:

1. `aurora-core.mdc`;
2. **один** из файлов `level-learning.mdc` или `level-development.mdc`.

Путь назначения:

```text
havn/
└── .cursor/
    └── rules/
        ├── aurora-core.mdc
        ├── level-learning.mdc      # ИЛИ level-development.mdc
        └── custom.mdc              # НЕОБЯЗАТЕЛЬНО: правила этого проекта
```

Важное различие: **единственный источник поддерживаемых правил** — `aurora_architecture/ai/cursor/`. Файлы в Havn — установленные копии для применения в Cursor, а не независимая версия стандарта. Если вы решите изменить общее правило, редактируйте его сначала здесь, затем переносите обновление в проекты.

При выборе другого уровня замените существующий файл уровня, не держите оба одновременно: оба имеют `alwaysApply: true`.

### Собственные правила проекта

Если нужны дополнительные ограничения, создайте **в самом проекте** файл `.cursor/rules/custom.mdc` с метаданными `alwaysApply: true`. Он необязателен и не входит в набор установочных файлов Aurora. Например:

```mdc
---
description: Project-specific agent rules
alwaysApply: true
---

# Project rules
- Follow the naming conventions defined in PROJECT.md.
- Keep user-facing interface text in Russian.
```

Правила Aurora задают общую основу, а `custom.mdc` — локальные предпочтения проекта. Локальные дополнения не должны отключать безопасность, честность проверок или требования к подтверждению действий. При противоречии агент должен сообщить о нём, а не выбирать правило произвольно.

**Обновления:** `aurora-core.mdc` и выбранный файл уровня обновляются из Aurora Architecture; `custom.mdc` остаётся под управлением самого проекта и не перезаписывается при обновлении Aurora.

Отдельная карточка `PROJECT.md` описывает конкретный проект (название, цель, стек, запуск). Она живёт в самом проекте, а не в Aurora Architecture.

## Обновление

Пока подключение и обновление выполняются вручную. Автоматический установщик или CLI относится к будущему этапу инструментов и не требуется для начала.

## Статус

Правила Cursor — стартовая версия для проверки на проектах. Запланированные стандарты из `STANDARDS.md` не следует автоматически считать утверждёнными обязательствами.
